## Section 2. Mechanisms confirmed correct

- `SessionStart` matchers `startup`, `resume`, `clear`, `compact`, `fork`, with `fork` separate since v2.1.214, and plain stdout added to context before the first prompt: `hooks.md:1098-1108`, `:1147-1160`.
- Only `command` and `mcp_tool` handlers run on `SessionStart`, so the map is a `command` handler: `hooks.md:1096`.
- Hook output strings, including plain stdout and `additionalContext`, are capped at 10,000 characters and spill to a file with a preview and a path: `hooks.md:916`, `:996`. The 9,500-character budget is the right response, and the 20,585-character measurement reproduces exactly when the shipped hook is run by hand.
- Hooks for one event run in parallel with no guaranteed order, so one script must print the ordered map: `hooks.md:417`; r1 section 4 (h).
- `claude --init-only --debug-file <path>` is the documented way to confirm `SessionStart` hooks ran, which is what requirement-map row 2 uses: `hooks.md:1236-1240`, `cli-reference.md:98`, `cli-reference.md:84`.
- `PreToolUse` deny through `hookSpecificOutput.permissionDecision` with `permissionDecisionReason`, most restrictive wins across hooks, and a deny holds even in `bypassPermissions`: `hooks.md:1741-1760`; r1 section 1.
- For `Write`, `Edit` and `Read`, `tool_input.file_path` is always absolute with `~` and relative paths already expanded, and Windows delivers backslashes that a hook must normalize: `hooks.md:1563-1568`. The design states both, correctly.
- `Bash|PowerShell` is the right matcher pair for shell commands, and on Windows without Git Bash the Bash tool is not registered at all: `hooks.md:1613-1617`. Both PowerShell and Bash inputs carry `tool_input.command`: `hooks.md:1594`, `:1609`.
- Settings-file and plugin hooks run inside subagents, and the input carries `agent_id` and `agent_type`: `hooks.md:270`, `:743`. The write guard's first deny condition is sound.
- A subagent loads every level of the CLAUDE.md hierarchy including project rules; Explore and Plan skip it: `sub-agents.md:1036`, `:1041` (see F15 for the live addition).
- Unscoped rules and the project-root CLAUDE.md are re-injected from disk after compaction; path-scoped rules reload only when a matching file is read again; hook-added context is summarized away; `SessionStart` hooks matching `compact` run again: `context-window.md:1601-1616`.
- Invoked skill bodies are re-injected at 5,000 tokens per skill and 25,000 total, truncation keeping the start of the file: `context-window.md:1614-1616`. The design's "put the rules that matter most at the top of each body" follows from it.
- `PostToolUse` returns `hookSpecificOutput.additionalContext` beside the tool result: `hooks.md:1964-1990`.
- `PreCompact` matchers `manual` and `auto`, blocking by exit 2 or `decision: "block"`, and blocking an automatic recovery compaction can fail the request: `hooks.md:2983-2991`. The design's decision to register `manual` only is right.
- `SessionEnd` cannot block a `/clear` and its JSON output is discarded, so a deliberate clear can only be covered by the handoff rule: `hooks.md:3246-3282`; r1 section 1.
- `${CLAUDE_PLUGIN_DATA}` exists, resolves to `~/.claude/plugins/data/{id}/`, survives plugin updates, and is exported to hook processes: `plugins-reference.md:697`, `:735-739`, `hooks.md:498`. It is also substituted inside plugin skills: `skills.md:416`.
- Exec form `"command": "node", "args": ["${CLAUDE_PLUGIN_ROOT}/hooks/<name>.mjs"]` is the documented cross-platform pattern, and path placeholders are substituted into `command` and each `args` element: `hooks.md:466-492`.
- A plugin cannot ship `.claude/rules` files or CLAUDE.md text, and plugin hooks live at `hooks/hooks.json`: `plugins-reference.md:89-95`, `:905-923`; r1 section 4 (d), re-checked live. Writing both rule files into each project from `project-init` is therefore the only route, and `project-init` copies rather than symlinks, which matters after the live change that drops path-scoped rules from approved symlinked directories (r1 section 3, item 1).

## Section 3. What the build should prove that section 10 does not list

1. The real byte count of the assembled map in a seeded project with every file at its cap, and which parts the overflow rule drops in that case. Section 10 proves that 9,500 characters can be printed, not that the map fits in 9,500.
2. That the injected marker command passes the permission check in a project with default permissions, and what happens under `disableSkillShellExecution: true` and in auto mode, where the command may not have run when the body is delivered.
3. Where a `PreCompact` `decision: "block"` reason is shown: the owner, the agent, or both. The design's hold message is written for the agent.
4. That each guard's `timeout` is short enough that the fail-open path at `hooks.md:848` is never reached in normal use, with a measured worst case for `git log`, `git status` and the checker on a large knowledge folder.
5. That the gate fires for a PowerShell call on a Windows machine without Git Bash, which is the case F4 shows it currently misses.
6. That a plugin `hooks/hooks.json` deny survives the owner's usual permission mode, including auto mode, and that a plugin hook does not need a separate trust step in Claude Code the way it does in Codex.
7. That `core.hooksPath` does not already have a value in each project `knowledge-setup` equips.
8. That the write guard's `if` pattern and the script's own path check agree after Windows backslash normalization, so the `if` never filters out a call the script would have denied.
9. That `git log -1 --format=%ct` behaves on a branch with no commits, a detached HEAD and a shallow clone, so the gate fails closed rather than crashing open.
10. That the 30-day housekeeping in `startup-map.mjs` cannot delete the state file of a session that is still running. It is the only destructive action in the design.
11. That the Stop nudge's continuation does not interact badly with another `Stop` hook in the same project, given the shared 8-continuation cap.

## Section 4. Verdict

**Pass with fixes.** Every mechanism the design leans on is real, most of the
detail is right, and the harness claims are cited more carefully than is usual.
Three things have to change before the build starts.

1. **The Stop nudge is not quiet on either harness** (F1). `additionalContext`
   on `Stop` continues the turn in Claude Code just as `decision: "block"` does
   in Codex. Section 8.4, the section 4 row, the walkthrough's "what the owner
   sees" line, and open question 13 all have to be rewritten around that.
2. **The startup budget does not fit the startup map** (F2). The design's own
   caps sum to roughly 16,900 characters against a 9,500-character budget, and
   the two files the checker caps already exceed it on their own. Per-part
   sub-budgets and a stated drop order are needed, or the ordered head and the
   order-independent tail have to be split across two `SessionStart` handlers.
3. **The marker injection line needs `allowed-tools`** (F3). Without a
   pre-approving rule an injected command whose permission check does not return
   allow aborts the whole `knowledge-save` invocation, which would take out the
   only sanctioned path for writing a lasting file.
