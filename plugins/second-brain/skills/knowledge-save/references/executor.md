# Assign and verify an approved save

The main agent owns selection, permission and the final report. Use a native
helper only when available and authorized. Follow host/project model and access
rules. Do not spawn a helper that cannot access the durable inbox record, or
assume a worker can outlive its parent. Retain one inbox, with no private queue.

Give the executor this explicit assignment with real values:

- Project/repository and existing publication checkout; current work item.
- Stable inbox reference, approved revision, and exact destination files.
- Operation and approved meaning; required verbatim text and source evidence.
- Durable permission location, source/person/date/scope and any current hold.
- `knowledge/knowledge-manual.md`, this knowledge-save skill, the applicable
  operation/template and the selected project output style. Read them before
  acting.
- Read current local and remote state first; coordinate other writers. Apply
  only the approved work, read it back, check meaning/fields/links, rebuild and
  validate indexes, then use the project's authorized publication route.
- Return the reference/revision, paths, actual checks, commit and verified remote
  evidence, publication/cleanup state and exact remaining action.

No extra memories, broader deletion or independent approval. A helper that lacks
access, tools, credentials, approval interaction or result delivery returns the
specific unfinished step. Main-agent foreground fallback uses the same authority
and procedure. Do not change account or authentication to make a test/save pass.

After dispatch, keep its host/session/worker/checkout in the inbox and use the
host's actual status when available. A stored ID is not a running worker. Before
retrying, inspect actual files and current remote; missing output does not mean
nothing happened. If worker status is unknown, avoid a competing edit in that
checkout and report the limit. Continue independent conversation.

On changed direction or cancellation, request a pause through available controls
and inspect actual changes. Check late results against the latest direction.
Do not assume cancellation undid a push, blindly replay an old approval, or
revert published content automatically. Bring changed meaning back to the main
agent, preserving the original permission. Parent/session interruption uses the
same inbox recovery; no renewed approval for unchanged authorized work.

Before reporting success, the main agent inspects the result, current destination
and remote verification. A valid metadata check is not a meaning review. Report
only checks actually run and distinguish destination publication from pending
inbox cleanup. Host support is demonstrated by actual concurrent execution and
result return, not by a helper name or a CLI version.
