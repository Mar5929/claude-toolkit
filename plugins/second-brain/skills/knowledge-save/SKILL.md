# Save and maintain project knowledge

This procedure's templates and recovery layout require the managed schema:2
manual. If the installed manual is legacy or the layout is partial/conflicting,
use `knowledge-setup` to reconcile under actual update authority before these
mutations. Until then preserve candidates and continuation in the existing
conversation/current-work route; do not create a new inbox or move files as an
incidental save. A newer plugin cache alone does not authorize migration.

Use the complete current `knowledge/knowledge-manual.md` already read at startup;
restore missing or changed guidance before dependent work. Read the project's
selected output style before authoring proposals or saved prose; reuse it while
current. Plain language must preserve useful detail and required exact wording.

1. Read [selection and cards](references/selection-and-cards.md) when reviewing
   candidates, requesting approval or interpreting an answer. Determine kind,
   scope and owner before applying memory eligibility. Route valid non-memory
   information to its own process; an unavailable owner is a reported gap.
2. Search the existing topic and inbox. Check current sources and permission.
   Read [operations and templates](references/operations.md) for the requested
   operation, then only the linked template for the destination. Do not widen
   an approval or infer approval from silence, an index, or an inbox state.
3. Read [execution and recovery](references/execution-and-recovery.md) before
   any authorized save or retry. Persist exact authority and owed scope in the
   single inbox before mutation or helper dispatch. Keep the same reference
   through retries. Inspect actual file/Git/remote state before replaying work.
4. When delegation is available and authorized, use the explicit
   [executor assignment](references/executor.md) while independent conversation
   continues. The main agent owns approval and verified reporting. If unavailable,
   finish in the foreground under unchanged authority and name the limitation.
5. Read back content and check meaning, sources, style, metadata and links.
   Rebuild indexes and run the installed checker. Publish through the project's
   documentation route and verify the remote. Then remove only the completed
   inbox entry and verify that cleanup was shared. A pending cleanup is distinct
   from an unpublished destination.

Routine no-change reviews stay quiet; direct save/review requests receive an
answer. Report completed memory/current-work saves briefly. Routine authorized
PRD upkeep after actual delivery stays quiet. Report failures and preserve
permission, completed steps and the next action. Pause only affected work.

A record/checker/receipt proves neither truth nor consent. The agent checks
meaning. These procedures add no automatic-save grant and no separate memory
store.
